# `@deepseek-ai/dsh-host-qq-mail-connector`

[English](README.md) | 中文

个人 `@qq.com` 邮箱的 Host 集成。连接器通过 `ctx.credentials` 保存邮箱地址和 IMAP/SMTP 授权码，通过 IMAP 验证账号，并暴露四个有作用域的 Harness 工具。它不使用 QQ 密码、浏览器会话或 `agently-cli`。

## 设置

先在 QQ 邮箱中开启 IMAP/SMTP 服务并生成授权码。然后在 Host 本机页面打开 Harness 连接器面板，输入完整的 `@qq.com` 地址和授权码，再选择“连接”。授权码是邮件客户端凭据，不是 QQ 账号密码。

默认 endpoint 是启用隐式 TLS 的 `imap.qq.com:993` 和 `smtp.qq.com:465`。部署可在 `cordis.yml` 中覆盖主机、端口、操作超时和响应上限。

## 安全与生命周期

只有 loopback 客户端可以保存或删除凭据，以及连接或断开账号。受信任的非本机客户端只能读取不含凭据的快照，其中包含状态、工具数量、安全错误字段和更新时间。断开时会先撤销四个工具，再由 UI 删除可写凭据。

IMAP 和 SMTP 客户端关闭协议日志，限制操作时间与响应大小，并统一认证和网络失败信息。读取结果不包含附件字节。

## 模型体验

### 已连接的个人邮箱工具

#### 模型看到什么

IMAP 验证成功后，包会注册四个工具：`qq_mail_list` 列出最近或未读的收件箱邮件，`qq_mail_search` 搜索邮件头和正文文本，`qq_mail_read` 按 IMAP UID 读取一封邮件但不返回附件内容，`qq_mail_send` 通过 SMTP 发送纯文本邮件。每个工具都会在连接 QQ 邮箱前请求一次 Harness 单次审批。邮件字段是不可信外部数据，绝不是指令。连接器会在每次操作时重新解析凭据，因此替换授权码会影响下一次调用，同时授权码不会进入浏览器、模型请求、结果、日志或公开状态事件。

#### Token 影响

四个固定 schema 占用稳定的请求前缀。只有相应的已批准读取操作执行后，邮件摘要和正文才进入上下文；发送结果包含 SMTP 投递元数据，而不包含提交的授权码。

#### KV Cache 影响

连接或断开会在受影响 preset 的下一次请求中增加或移除同一组四个工具 schema。凭据和连接器状态值不会对模型可见。

## 已知限制与暂缓工作

- 第一版暂不支持附件下载、收件箱以外的文件夹、删除邮件、回复、转发或富文本 HTML 编写。
