# Agent Note: 内置装甲 HUD 主题

Status: implemented

[English](2026-08-16-built-in-armor-hud-theme.md) | 中文

## 问题

Web 应用需要一种表现力鲜明的电影化界面选项，同时不能替换现有中性主题，也不能依赖受保护的系列作品素材、名称或标志。仅换颜色的第三方主题注册无法形成完整的产品选项，因为它不会出现在“外观”设置中，无法通过内置 settings schema 持久化，也无法在客户端插件树激活前应用主题专属字体和全局显示细节。

## 决策

`armor` 与 `light`、`dark` 和 `system` 并列，成为内置且可持久化的主题偏好。它采用深色原生控件配色，并在“外观”设置中显示为“装甲 HUD”。Host 引导代码与 `ThemePresenter` 都会把解析后的 id 写入 `body[data-dsh-theme]`；引导代码还会在加载外壳渲染前写入深色调色板属性，插件激活后则由呈现器拥有并撤销这两个属性。

`armor.css` 拥有该主题的原创视觉语言：碳黑表面、反应堆红操作、电弧青信息与边框、方角控件、系统等宽字体栈、硬边层级阴影，以及静态扫描线覆盖层。颜色仍通过语义 `--dsw-*` 别名进入功能组件 CSS；具名 body 属性仅用于无法表达为颜色 token 的主题全局细节。注册的扩展主题继续采用别名 token 覆盖，并且只在进程内有效。

settings schema、组件测试、Host 校验、引导测试、呈现器测试和组装后的浏览器设置场景都接受这一内置 id。浏览器场景通过真实的“外观”控件选择“装甲 HUD”，并验证主题 id、深色调色板、字体、持久化设置值、页面重载，以及共享同一 Harness home 的第二个 origin。

## 曾考虑的替代方案

**替换现有深色主题。** 否决。电影化处理有意比通用深色调色板更强烈，用户仍需保留中性选项。

**将装甲 HUD 注册为扩展主题。** 否决。扩展 id 按设计不会跨越 Host settings schema，也不会由内置“外观”设置列出，因此用户选择无法在重载后保留。

**复制 Marvel 角色、标志或电影界面。** 否决。产品需要原创且可再分发的身份；本主题只采用电影化 HUD 这一宽泛类型，不使用受保护的素材或系列品牌。

**把所有视觉差异编码为内联主题 token。** 否决。引导代码必须在 ThemeRuntime 激活前建立该视觉处理，而字体、方角几何和扫描线覆盖层属于全局 CSS 行为，不是语义颜色值。

## 后果

用户可以选择并持久化鲜明的电影化像素 HUD 风格，同时保留所有既有主题。呈现器新增一个自有 DOM 属性，此后每个内置偏好都必须同时在 Host 引导代码与 ThemeRuntime 中保持有效。视觉处理集中在 `ui-theme`；功能包继续消费语义 token，不携带任何装甲主题专属选择器。该主题有意以中性主题的排版紧凑度换取更强氛围，同时保留焦点状态、可读对比度、指针行为，以及静态且兼容减少动态效果偏好的视觉细节。
