# Agent Note：通过 GenOffice 本地编辑 PPTX 文本框

Status: implemented

[English](2026-08-27-web-genoffice-pptx-editing.md) | 中文

## 问题

Agent 生成的 PPTX 可以交给外部服务预览，但正式 Web 应用无法在对话旁保留幻灯片布局并编辑演示文稿文本。目标交互是本地的：点击生成的演示文稿，在右侧工件栏中编辑，再保存回同一路径，且不需要服务凭据或上传生命周期。

## 决定

正式 Web 组合启用本地 `genoffice-pptx` 工件 provider。Host 通过固定版本的 GenOffice PPTX 引擎解析文件，以 SHA-256 源文件修订值创建不透明进程内 grant，并返回幻灯片尺寸、背景、顶层元素几何关系、图片、形状和文本框。配置的大小上限同时约束压缩源文件和 OOXML 解压后的完整 JSON 投影。

浏览器渲染带幻灯片列表、标题栏、格式功能区和等比例画布的 PowerPoint 式工作区。符合条件的顶层文本框可以原位编辑；选中文本框后，可以统一调整字体、字号、粗体、斜体、下划线、文字颜色和段落对齐。包含字段、超链接、混合 run 格式或混合段落对齐的文本框保持受保护，因为通过统一编辑器替换它们会丢弃尚未支持的语义。组合、表格、图表、passthrough 元素、继承装饰、幻灯片顺序和元素几何关系只用于显示。

保存操作通过 `host.saveGenOfficePptxArtifact` 发送发生变化的文本框。Host 重新打开当前字节，校验幻灯片及元素 index，验证 grant revision 与当前文件 hash，应用完整文本和统一格式替换，并通过同目录临时文件原子替换工作区原文件。GenOffice 只修补发生变化的文本及段落属性，保留未触及的 OOXML package entry。磁盘文件变化会返回 `artifact-preview-conflict`，且不会覆盖它。

启用后，本地 PPTX 准备优先于已配置的外部 Office provider。部署可以关闭该能力并保留原有外部预览行为。

## 考虑过的替代方案

- **嵌入 GenOffice Electron renderer**——它依赖 Electron preload API，并不是可嵌入的 Web component。
- **把幻灯片渲染为彼此断开的文本行**——会丢失使演示文稿可理解、可编辑的空间关系。
- **立即提供逐 run 的富格式编辑**——在本地保存路径得到验证前，就需要实现选区编辑，并安全重建混合字段、超链接和继承样式。
- **让所有幻灯片元素都可编辑**——结构编辑需要独立的插入、删除、媒体、关系和布局操作；把这些能力显示为可用会夸大本次实现范围。

## 后果

现在可以在右栏中按原始位置打开生成的 PPTX。用户可以编辑符合条件的文本框和常用的整框格式，再保存回工作区中的同一路径。真实引擎单元测试会重新解析保存后的字节并覆盖外部修改冲突；client 测试覆盖画布、工具栏、草稿与保存状态；无密钥的组装 Web 场景会编辑真实 PPTX，并从磁盘重新解析保存后的文件。

这不是完整的 PowerPoint 替代品。它不能新增、删除、缩放或重排幻灯片及元素，并会保护混合格式和复杂结构。XLSX 编辑仍属于独立 capability 切片。
