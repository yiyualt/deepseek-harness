# Agent Note: 人工产物编辑进入 Agent 上下文

[English](2026-08-28-human-artifact-edit-awareness.md) | 中文

Status: implemented

## Problem

Web 产物编辑器会把人工修改保存到工具共同使用的 workspace 文件中，但模型可能继续依据对话历史工作，而不知道文件已经变化。通过对话发送完整 HTML、Markdown 或 OOXML 内容会重复 workspace 状态、消耗无界上下文，并错误地让消息而非文件成为权威内容。保存完成到下一次提示词之间还可能发生进程重启，因此通知必须独立于浏览器状态存活。

## Decision

每次内置 HTML、Markdown、DOCX、XLSX 或 PPTX 保存都会在 Host RPC 中标识所属会话。Host 在写入前解析该会话，提交带 revision 检查的原子文件替换，追加包含规范路径、格式和已保存 revision 的 `artifact/edited` 会话事件，并在确认保存前刷新会话。会话缺失或不可用时，系统会在文件变化前拒绝请求。

API 网关安装一个 `agent/pre-step` 监听器。它扫描最近一条已记录 `artifact-edit` 上下文之后的持久编辑事件，最多取配置项 `artifactEditNoticeMaxItems` 指定的数量，并向下游 enter 决策追加一条 user role 通知。通知列出变化路径，并要求模型把当前磁盘内容视为权威内容且重新读取文件。其 source 记录最后一个已覆盖事件的序号，因此已经提交的上下文不会重复交付；若消息获准进入前发生崩溃，编辑仍会留待下一步骤处理。其余待处理编辑会在后续步骤中以有界批次继续推进。

保存不会唤醒空闲 agent（智能体）。编辑会加入正在进行工作的下一步骤，或加入下一条人工提示词触发的请求。持久编辑事件记录感知状态；workspace 文件仍是内容真源。

## Alternatives considered

- **保存后直接调用 `agent.inject()`** — 实现简单，但文件重命名与 inbox 变更之间若发生进程故障，唯一通知会丢失；持久编辑事实可以在重启后回放。
- **把完整编辑文档作为上下文发送** — 这会复制可能很大或为二进制的内容、让 OOXML 投影占用上下文，并可能与后续磁盘状态不一致。通知只携带文件身份，工具负责读取权威文件。
- **每次保存都唤醒 agent** — 这会在用户仍在编辑时启动未经请求的模型轮次，并可能让多个快速保存相互竞争。非唤醒交付保留明确的轮次所有权。
- **监视所有 workspace 文件** — 外部文件系统观察无法可靠识别人工编辑者，还会增加平台相关的监听生命周期，并对 agent 自己的工具写入发出通知。本功能只记录 Host 认证的内置编辑器保存。

## Consequences

通过五种内置产物编辑器完成的人工修改都会成为持久且模型可见的上下文，同时不会把文档正文复制进会话。正在进行的工作会在下一步骤观察到编辑；空闲会话会在下一条提示词启动工作时观察到编辑。多次保存保持顺序和边界，对话 transcript 会记录每条获准进入的编辑通知。外部应用或直接文件系统操作产生的变化仍只能由 agent 重新读取文件来发现，不会生成 `artifact/edited` 事件。

现有 HTML、Markdown、DOCX、XLSX 和 PPTX Agent Note 继续负责各编辑器的投影、冲突处理与写回行为。本决策只新增共享感知生命周期，不取代这些记录。
